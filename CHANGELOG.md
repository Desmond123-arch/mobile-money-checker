# Changelog

Notable changes to momo-spend. For why and how the data layer should replace the stand-ins listed here, read [`docs/handoff.md`](docs/handoff.md). Commit history has the detail; this file is the map.

The app is a local-first proof of concept. Screens read and write SQLite. Real messages get in by importing an SMS Backup & Restore XML file, or by reading the phone's inbox. Inbox reading is written and tested against a fake module but has never been compiled or run on a phone. "Lock the app" is a stand-in.

### What is left

- **Live SMS reading, on a device.** Compile `modules/momo-sms` in an EAS dev build, then run the manual test list in `docs/handoff.md` (delete-newest then receive another, id reuse, restricted settings on Android 13+ with a sideloaded APK, the MIUI hidden-sender toggle, the observer, the foreground trigger). Until then treat it as unverified.
- **Device checks.** Everything above ran on an emulator or in Node. Nothing has run on a real phone, including the file picker, the foreign-key setting in `src/data/db.ts`, and layout with 27 months or long names.
- **Maestro.** Not installed here, and the flows assume sample data and a Home launch. They need a seeded fixture or test mode.
- **Release build.** Strip `INTERNET` from release builds so the Privacy screen's claim is true. Adding `READ_SMS` did not change it; the manifest still has `INTERNET`.
- **App lock.** The toggle is a stand-in.
- **Reparse.** A parser version bump should re-read messages and move user annotations when a transaction id changes. Not built.
- **Validation.** The 70% categorisation target needs a second phone. Fixtures and the denylist hygiene check need a skim before the first public push.
- **After the proof of concept.** Budgeting (per-category monthly limits, alerts). `docs/data-model.md` has the migration sketch and the schema already leaves room for it.

## Unreleased

Entries are grouped by area, not by PR; the table above maps work to pull requests.

### Added

- **Live SMS reading (built, unverified on a device).** `modules/momo-sms`, a local Expo module (Kotlin, `READ_SMS` only) with permission status and request (`granted`, `denied`, `blocked`, `undetermined`), a list of `(id, receivedAt)` for the `MobileMoney` sender, reads by id with `<#>` OTP bodies dropped in Kotlin, and a foreground `ContentObserver` with a 1 s debounce. `src/scan` is a single-flight scan: it diffs the inbox against stored inbox rows (new, replaced, missing, reused id, returned), reads unseen ids in pages of 500, ingests them and runs `finishScan`. Triggers are cold start, the app becoming active, the observer and a Settings row, "Check for new messages". "Allow SMS access" now asks for the permission and runs the first scan behind Importing with real progress. Denied has "Try again"; blocked explains Android 13+ restricted settings; a granted permission with no MobileMoney messages has its own screen with the MIUI, Tecno and Infinix hint. Home shows an "SMS access is off" banner over stored data. Only `src/scan` may import the module (ESLint). An inbox message that fails to ingest is stored as an `error` row. The Kotlin was written without an Android SDK and has never been compiled.
- **SMS parser (`src/domain/parse`).** `parseSms` for all 11 MoMo message shapes plus OTP, no-transaction-id and failed-payment classification; `mergeAll` (commutative per-field merge of a transaction's messages); `linkReversals`; `reconcileBalances`; `parseBodyTime` in `src/domain/time.ts`. On the sample export (2,488 messages) 1,913 of 1,919 transaction-labelled messages parse; the other 6 are failed payments and are ignored. Dev tools: `npm run check:sms -- <export.xml>` (real-data check) and `npm run anonymise:sms -- <export.xml>` (writes `fixtures/sms`). Branch `feat/sms-parser`, into `dev`.
- **SQLite layer (`src/data`).** `Db` interface and `openDatabase` over `expo-sqlite` (WAL, foreign keys on, exclusive transactions), a `PRAGMA user_version` migrator, and migration `0001_init`, chosen from three candidate schemas (see the arena record in `docs/data-model.md`). Every table is STRICT. Observed (`sms_messages`, `sms_fragments`), derived (SMS `transactions`) and user-owned (`transaction_annotations`, `message_dismissals`, config, manual transactions) data live in separate tables. The categoriser writes `transactions.auto_category_id`; the user's tag lives only in `transaction_annotations`. The `ledger_lines` view is the single accounting rule: refunds net into the original's month and category, capped at the original amount. Triggers protect the five system categories and SMS rows even when foreign keys are off. `seedDatabase` adds the UI categories once per seed version. Deliberate changes to `system-design.md` section 6 are listed in `docs/data-model.md`, which supersedes it. Tests run on Node's `node:sqlite`.
- **Insights calendar.** The period pill opens a sheet with a Day and a Month switch. A day replaces "Where it went" with that date's spending, an empty state for days without payments, and a "not happened yet" state with an average day of that name. Pure helpers in `src/domain/calendar/week.ts`.
- **Add an expense.** A "+" on Home and Transactions opens a sheet (amount, what for, category, Today or Yesterday). Expenses are tagged "Added by you" and count towards Home's totals, categories and recent list. Saved as a manual transaction (see the write-side entry below).
- **Month picker.** The month pill on Home opens a sheet; the choice drives Home and Insights (`PeriodProvider`).
- **Filters and search.** Category filter sheet (from Home's filter button and the Category pill), a search field on Transactions, and a Clear button.
- **Messages we couldn't read.** Ignore, Copy text, Add by hand, empty state.
- **Privacy screen**, hidden categories expanding in Settings, inline add-name chips, delete-category confirmation.
- **Home totals row:** Money in, Payments and A day (average spend per day so far), three equal centered columns. `dailyAverage` in `src/domain/summary/month.ts`.
- `allocate` (splits a total by weights so the parts sum exactly) in `src/domain/category/share.ts`.
- Maestro flows for each interaction (`maestro/flows`), project verification skill (`.claude/skills/verify-momo-spend`).
- **Backup import, everything except the parser and ledger** (spec 5.1a, FR-19; design 3.1; system design 7.9).
  - `sms_messages` gets `source` (`inbox` or `backup`), a nullable `android_sms_id` and a `backup_key` identity (`<received_at>:<momo_txn_id>:<template_name>`). Edited into `0001_init` because it is unreleased. `source_on_phone` and `unread_messages` count inbox rows only.
  - `src/backup`: a streaming reader for SMS Backup & Restore XML (`readBackupMessages`, `countBackupMessages`) that runs on any byte source, Expo adapters (`pickBackupFile`, `openExpoFile`), the `importBackup` orchestrator with an injected `ingestBatch`, and a progress store.
  - Permission screen has "Import a backup file", which opens the steps sheet (`/sheets/import-steps`) and its "Choose file" button. Importing shows real read and total counts. Payments are not counted until the parser is connected.
  - New dependencies `expo-document-picker` and `expo-file-system`; Maestro flow `import-backup.yml`.

- **Real backup import (`src/ledger`, `src/features/app`).** Importing a backup file now writes real rows. `ingest` parses each batch in one transaction with a savepoint per message, stores parsed messages and fragments, and re-derives each transaction with `mergeAll`, so re-importing or reordering gives identical rows and a user's annotation survives. `finishImport` links reversals and refunds and sets `meta.first_import_done`. All ledger writes go through one single-flight `writeQueue`. `DbProvider` migrates and seeds the database at startup. The Importing screen counts real payments and ends on "Import complete" with a summary (transactions, payments, spend for the latest month) and a Go to Home button. On the sample export: 1,913 parsed, 575 ignored, 1,640 transactions, 6 reversal links. Home and the other screens read these rows from the read-queries entry below.
- **The categoriser (`src/domain/categorise`, `src/ledger/categorise.ts`).** `resolveCategory` applies recipient rule, family and friends names, keywords, built-in counterparty rules, type default, Misc, in that order (`docs/categorisation.md`). Fuzzy matching: tokens of 5 to 8 letters allow one edit, 9 and over two, under 5 none, and the first and last letter never change. Seed keywords are in `src/domain/categorise/seed.ts` with the duplicate words removed; seed step 2 adds them to the database once per seed version, adds Electronics, Entertainment & Subscriptions, Personal Care, Giving, Savings & Investing and Services, and orders the keyword categories by priority in `sort_order`. `ingest` sets `auto_category_*`, `reference_clean` and `is_self_transfer` (from `meta.owner_number` and `owner_name`, both unset today). `recategorise(db)` rewrites the auto category for all SMS rows in one transaction, and `finishImport` calls it. `resolveCategoryStub` is gone. `npm run check:categories -- <export.xml>` prints the category split and redacted skeletons of unmatched references. On the author's own export, 77.1% of outgoing non-cash-out transactions land outside Misc (42.1% Airtime & Data from built-in rules, 24.7% Food); that phone was used to write the rules, so the 70% target is not yet measured on a fresh phone.
- **First-run gate and Settings import row.** A fresh install now opens on Permission instead of Home (`FirstRunGate`, `decideStartRoute`, `meta.onboarding_choice`; rules in `docs/handoff.md` section 5). "Not now" saves the choice and goes to Home; it no longer opens Permission denied. Settings, under More, has "Import a backup file", which opens the same steps sheet and shows "Last imported <date>" (`meta.last_import_at`, set by `finishImport` on every run). `getMeta` and `setMeta` in `src/data/meta.ts`. Maestro: `setupApp.yml` skips onboarding through `_skipOnboarding.yml`; new `first-run-gate.yml` and `settings-import-row.yml`; `permission-flow.yml` now ends on Home. "Allow SMS access" is unchanged and still has no scan behind it.

- **Read queries and real screens (`src/data/queries`, piece 4a).** Home, Transactions (list, search, filters and detail), Insights and the month and calendar sheets now read SQLite instead of `sample.ts`. Typed read functions over `ledger_lines` and `transaction_list` (months with data, month summary and per-day spend, category spend for a month or day, recent payments, the grouped list, detail, needs-a-note, six-month flows, weekday averages), TanStack Query hooks per feature, and a `QueryProvider` that invalidates everything when an import finishes. `categoryById` reads the `categories` table (UI id is the system key, `misc` stays `other`, user categories use their row id). The period opens on the latest month with data when the current month is empty, and says "No payments in <month>." when a month is empty. On the sample export the latest month (June 2026) reads 28 payments, GHS 1,925.56 out and GHS 1,960.00 in. Dead constants `MONTH_OPTIONS`, `CURRENT_MONTH`, `SAMPLE_*` and the sample files for Home, Transactions, Insights and Categories are removed. Maestro flows that assert sample data now fail (list in `docs/handoff.md` section 6). New test ids: `homeLoading`, `detailLoading`, `detailNotFound`, `insightsMonthEmpty`.

- **Write side (`src/ledger`, piece 4b).** Every button that looked like it saved now does, through the write queue in one exclusive transaction, followed by react-query invalidation by key prefix (`useWrite`). Add expense stores a `manual` transaction with its category as an annotation, so Home, Transactions and Insights see it through the same views; `ExpensesProvider` and `merge.ts` are deleted. Detail Save changes, Add note and Cash-out write notes, tags and snoozes to `transaction_annotations` (only changed fields; `''` clears the SMS note). "Always tag this recipient" saves a `recipient_rules` row scoped by flow and recategorises. New category, add and remove word and delete category (system-design 7.8, with counts in the confirmation) write `categories` and `keywords` and recategorise; a word belongs to one category and a name to one list, and the UI says which when refused. Family and friends names read and write `name_lists`; word counts come from `keywords`. Messages we couldn't read lists the `unread_messages` view, Ignore writes `message_dismissals` and Add by hand creates a manual expense linked through `source_message_id`. All category pickers use `useCategories()`. Tests on `node:sqlite` close and reopen a file database to prove each write survives a restart. Settings sample data (`sample.ts`) is deleted. New domain helpers `normaliseWord`, `tintOf`, `isHexColor`.

### Changed

- "Ask me later" on the cash-out sheet now works. `cashOutPrompts` reads cash-outs with no user note and no manual category, at or after `meta.first_import_at`, not snoozed. The Transactions `cashOutLink-<id>` shows only while the prompt is live, and Home's needs-a-note card counts cash-outs with the other payments and opens the newest cash-out first. Old cash-outs from an import are not asked about.
- Privacy screen copy matches what the app does: no claim about internet access (the permission is not stripped from release builds yet), SMS access is optional because a backup file can be imported, fee and tax are listed as kept, and the backup import's temporary copy is described.
- "Messages we couldn't read" shows a time and a reason instead of message text, because text is never stored, and is empty after a backup import. "Copy text" is removed with it. "Lock the app" says it is not built yet. The edit-category suggestions are now seed words the user removed. A cash-out in Cash shows a "What was this for?" link on Transactions.
- The yellow "Add a note" state on a row now means a payment out in Misc with no note (it used to be any row with no note). The detail screen shows "about" before a time taken from the SMS received time, hides "Balance after" when there is none, and no longer pretends it can show the original message.
- Text line heights raised to at least 1.3x the font size, fixing clipped y, g and p on Android.
- Screens and sheets use `KeyboardAvoidingView`, so inputs sit above the keyboard.
- Copy text loads `expo-clipboard` lazily, so a dev build without the module does not crash Settings.

### Removed

- Fees and tax from the UI (Home totals, transaction detail). The domain still models fee and tax for the parser.
- The weekday bar chart on Insights (replaced by the calendar).
